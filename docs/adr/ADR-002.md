# ADR-002: Field annotation via typing.Annotated + Mode metadata
## Status
Accepted — 2025-09-18

## Context
We need a typed, declarative way to mark which fields belong to which modes without inventing a new Domain Specific Language(DSL).

## Decision
Use `typing.Annotated[T, Mode("dto","frontend","llm", default=False)]` to attach mode metadata to fields. They can then be converted via model_dump(mode='[mode name]'). Configurable default include and exclude mode.

## Consequences
- Standard Python typing; works well with Pydantic v2.
- Metadata rides with the field; discoverable for slicing/schema.
- Nested models must propagate/merge mode metadata correctly.

## Alternatives
- Custom decorators per field (verbose, not type-driven).
- Custom per class instance converter between types. 
- External YAML/JSON configs (desync risk, multiple source of truth).

## Risks
- Interaction with inheritance and generics needs tests.
- Annotated metadata must not break IDE/type-checking.

## Follow-ups
- Add more unit tests for nesting/inheritance.
