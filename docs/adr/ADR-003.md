# ADR-003: Default-deny policy & conflict resolution
## Status
Accepted — 2025-09-18

## Context
Fields can be untagged or tagged inconsistently across modes. We need deterministic, safe behavior.

## Decision
1) **Default-backend**: untagged fields are by default set as backend (highest security level) but default behaviour is customizable per class and per field. default_include_modes states annotation are default included
default_exclude_modes states what modes to exclude when model dump does not specify a mode.
2) **Conflict resolution**: Default exclude overrides default include, retaining information unleaked is at higher priority than information availability. Pydantic model_dump include exclude behaviour overides all.

## Consequences
- Safer by default; prevents accidental leakage.
- Deterministic rule (union, then explicit exclude).
- May require tagging more fields up-front.
- Compatible with pydantic

## Alternatives
- Default-allow (less safe).
- Priority by annotation order.

## Risks
- Surprising to teams expecting permissive behavior.

## Follow-ups
- Add invariant tests:
  - Untagged fields aren’t in `frontend`/`llm` slices.
  - Explicit exclude beats include.
