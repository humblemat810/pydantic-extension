# ADR-005: Runtime dump/filter semantics (model_dump(field_mode=...))
## Status
Accepted — 2025-09-18

## Context
Even with mode-projected models, callers may dump a full model or depend on the default include exclude config. We need a uniform runtime filter.

## Decision
Augment dump semantics:
- `model_dump(field_mode="dto")` filters using the same rules as slicing.
- Provide `field_mode=None` (no filtering) for internal/backend use.
- Provide `strict=True` to raise if an untagged field slips into a filtered dump.

## Consequences
- Uniform behavior: schema and runtime align.
- “Strict” gives a hard guardrail to catch leaks in tests.
- Some overhead to compute filtered dicts.

## Alternatives
- Per-call `include/exclude` dicts (brittle).

## Follow-ups
- Add tests: strict mode raises; nested models respect `field_mode`.
