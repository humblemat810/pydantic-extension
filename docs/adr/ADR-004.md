# ADR-004: OpenAPI/schema generation for mode-specific models
## Status
Accepted — 2025-09-18

## Context
APIs/clients should see only the fields in their mode (e.g., DTO). OpenAPI must reflect slices to prevent client/server drift.

## Decision
Expose a utility to construct **mode-projected models** at import time or lazily:
- `User_for_dto = slice_model(User, mode="dto")`
- Integrate with FastAPI by referencing the projected model in route signatures.

## Consequences
- OpenAPI shows the correct fields per endpoint.
- Clients generated from OpenAPI won’t see backend-only fields.
- Slight startup overhead when generating projected models.

## Alternatives
- Custom OpenAPI filters (harder to keep in sync).
- Manual DTO classes (duplication).

## Follow-ups
- Add tests: nested models, unions, inherited fields in OpenAPI.
