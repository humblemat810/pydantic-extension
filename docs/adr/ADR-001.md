# ADR-001: Mode slicing as first-class concept
## Status
In-effect — 2025-09-18

## Context
Models often serve multiple contexts (DTO/backend/frontend/LLM). Copy-paste models or ad-hoc `exclude`/`include` dicts lead to drift, leakage (e.g., backend-only fields to frontend/LLM), and duplicated logic. Combining would allow developer to stay focus in maintaining single class. The DTO model requires developers to maintain more than 1 model at possibly spreaded across different file locations that gives potential disagreement errors.

## Decision
Introduce **“modes”** as a first-class concept. A model can be **sliced by mode** to produce a context-specific view (e.g., `User["dto"]`, or `model_dump(field_mode="llm")`).

## Consequences
- Eliminates a class of data-leak bugs by making context explicit.
- Reduces copy-paste DTOs; single source of truth.
- Requires a small layer to track mode metadata and compose slices.

## Alternatives Considered
- Per-context DTO/ Backend/ Frontend/ LLM classes (high duplication).
- Per-call `include/exclude` dicts (brittle, easy to forget).
- Codegen of DTOs (heavier toolchain, drift risk).
