# ADR-006: Dynamic Model Slicing via `__class_getitem__` {#adr-006-classgetitem}
## Status
Accepted — 2025-09-18

## Context
We want a concise, Pythonic way to obtain a **mode-specific variant** of a Pydantic model at *type-level* (not only at runtime).  
Examples:
- `User["dto"]` → a projected model including only fields tagged for DTO.
- `User["llm"]` → a projected model excluding backend-only fields.
- These projected models should behave like proper `BaseModel` subclasses: compatible with FastAPI type hints, schema generation, and IDE autocompletion.

Naive alternatives (e.g., `slice_model(User, mode="dto")`) work at runtime, but are verbose, less discoverable, and break the natural Python idiom of “indexing into a parametrized type.”

## Decision
Implement `__class_getitem__` on models that opt into slicing:
- `MyModel["mode_name"]` returns a new subclass with:
  - Filtered fields per mode annotations.
  - A `__mode__` attribute storing the selected mode.
  - The class `__name__ ` attribute change with mode name appended
- These sliced models participate in schema generation (see ADR-004) and runtime dumps (see ADR-005).

## Consequences
- Concise, Pythonic syntax (`User["dto"]`), consistent with `typing` generics.
- Makes slices **first-class models**: usable in type hints and OpenAPI.
- Enables IDE tooling to show correct fields per mode.
- Slightly unconventional (not all devs know `__class_getitem__`).
- Risk of confusion with typing generics — must be documented clearly.

## Alternatives
- Explicit function: `slice_model(User, "dto")` (clearer, but more verbose).
- Per-mode subclasses manually defined (`class UserDTO(User): ...`) (duplicated, brittle).
- Custom metaclass dispatch (overkill, less idiomatic).

## Risks
- If not documented, `__class_getitem__` may be mistaken for a typing-only feature.
- Future Pydantic/typing changes may require adjustments.

## Follow-ups
- Add tests:
  - `assert issubclass(User["dto"], BaseModel)`
  - `assert "backend_field" not in User["dto"].model_fields`
  - OpenAPI generated for FastAPI endpoints using `User["dto"]` includes only allowed fields.
- Add docstring + README section explaining `__class_getitem__` usage and intent.
